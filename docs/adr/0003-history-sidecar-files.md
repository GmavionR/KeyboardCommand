# 每条历史记录使用元数据与正文两个文件

每条历史记录使用同一记录标识配对的 `.meta.json` 与 `.md` 文件：前者存放创建时间、来源文件夹、实际纳入的文件列表及正文文件名，后者只存放原样文件上下文包。选择双文件布局是为了让历史正文保持可直接查看和复制的 Markdown 文本，同时独立读取结构化元数据；代价是文件系统无法将两份文件作为一个事务提交，因此新增时先完成正文再发布元数据，删除时先删元数据，并清理孤立正文。替换历史时先写成新文件对再移除旧文件对。

主流的等价做法是单个文件先写临时文件、再原子重命名覆盖，而不额外使用发布标记文件。本项目保留元数据发布标记，是为了让 `.md` 正文始终是可直接打开的纯 Markdown，代价是必须配一条清理孤立正文的流程。落地时两层保障叠加：每个文件自身先写 `.tmp` 再重命名覆盖，保证单个文件不会被写坏；元数据作为发布标记，保证一条记录不会只落了一半。目录位置、记录命名与读取失败语义见 [issue 48](../../.scratch/folder-content-copy/issues/48-history-snapshot-storage.md)。
