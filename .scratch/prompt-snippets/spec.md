# 提示词片段（Prompt Snippets）产品技术规格说明书

Type: spec
Label: ready-for-human
Status: ready-for-human

## 问题陈述

用户在日常开发、对话式 AI（ChatGPT/Claude）、代码审查与文本交流中，频繁需要将成段结构化、推理严密的 Prompt（如详细解释、代码重构、总结归纳等）快速发送到当前正在使用的应用程序窗口中。

此前用户通过本地 AutoHotkey（AHK）脚本维护一份固定在代码中的 Prompt 列表数组，按下热键时弹出 AHK GUI List 列表，上下选择条目后回车发送到当前活动窗口，或由 AHK 的 InputHook 拦截特定缩写触发发送。
该机制存在以下痛点：
1. **数据与代码耦合**：提示词硬编码在 AHK 脚本中，修改、新增或阅读长篇多行 Prompt 体验极差，难以与外部 Markdown 知识库协同管理；
2. **缺乏可视化管理**：缺乏现代化的界面来浏览、搜索、编辑、配置存储路径及外部联动；
3. **与整体工具链割裂**：未能纳入 KeyboardCommand（KbcApp）这一统一的键盘效率中心，且在多工具协作时缺乏标准化外部消息调度通道。

因此，需要在 KbcApp 中建立专门的**「提示词片段」（Prompt Snippets）**模块。同时，必须严格恪守 KbcApp **“整体内存占用限制在 40MB 以下，严禁引入高内存组件”**的性能铁律。

## 解决方案

为 KeyboardCommand 建立**提示词片段（Prompt Snippets）**功能：

1. **双层形态：主窗口独立管理页 + 快捷粘贴悬浮窗**：
   - **管理端（`/prompts`）**：在 KbcApp 主窗口提供完整的管理界面，支持查看卡片、实时搜索、路径配置、表单增删改查、以及在文件资源管理器或外部编辑器中打开。
   - **使用端（快捷粘贴悬浮窗）**：在任意外部软件中工作时，通过全局热键、命令行或外部消息秒级唤起轻量选择器，过滤选中后自动隐藏并将文本粘贴至前台目标窗口。
2. **复用单套独立浮层容器（遵循 ADR-0005，恪守 40MB 内存红线）**：
   - 不额外创建新的 Webview 实例，而是直接复用既有的命令面板独立浮层窗口容器；
   - 通过前端路由与状态模式无缝切换（命令面板模式 vs 提示词选择模式），实现 0 毫秒级秒开的同时，全局 Webview 实例数保持为 2（主窗口 + 唯一浮层），避免多窗口导致内存翻倍。
3. **基于 `WM_COPYDATA` 的 Windows 消息激活（遵循 ADR-0006）**：
   - 为 AutoHotkey V2 等外部脚本提供零延迟、零额外常驻进程与端口占用的原生 `SendMessage(0x004A)` 控制通道；
   - AHK V2 负责轻量高效的全局击键 InputHook，拦截到触发词时直接通过 `WM_COPYDATA` 调度 KbcApp 或直接完成插入；KbcApp 专注提供数据源与可视化选择器。
4. **本地 Markdown 文件存储与 YAML FrontMatter 规范**：
   - 提示词以独立 `.md` 文件存储于用户指定的提示词目录（默认 `%APPDATA%/KeyboardCommand/prompts/`），每个文件对应一个条目；
   - 采用通用 FrontMatter 规范存储 `title` 与 `command`（触发词），正文存储原始文本；
   - 标题与文件名严格双向同步并清洗 Windows 非法字符；遇到同名时提示用户或覆盖；
   - 具备高度鲁棒的容错机制（缺失 FrontMatter 或语法错误时自动优雅降级，不崩不白）。
5. **零冲突键盘导航与实时搜索**：
   - 悬浮窗打开时焦点始终处于顶部搜索框中，打字立即实时过滤；
   - 上下方向键（Up/Down）和回车键（Enter）由列表接管，实现无需按键切换的无缝快速选择。
6. **剪贴板注入与自动还原保护机制**：
   - 选中提示词后，悬浮窗隐藏并退回原活动窗口焦点；
   - 备份当前系统剪贴板 -> 写入提示词文本 -> 模拟触发 `Ctrl+V` 粘贴 -> 延时 400ms 自动还原原剪贴板内容，杜绝剪贴板污染。

## 领域模型与术语定义

严格遵循项目根目录 [`GLOSSARY.md`](../../GLOSSARY.md) 的标准定义：

- **提示词片段（Prompt Snippets）**：管理和快速插入常用文本片段（如 AI Prompt、代码模板、快捷回复）的功能模块。
- **提示词（Prompt Snippet）**：一条具体的提示词片段条目，对应一个本地 Markdown 文件，由标题、正文以及可选的触发词组成。
- **触发词（Keyword）**：为提示词配置的简短缩写或代号，用于快速检索或热字串匹配。属性名称沿用 `command`。
- **提示词目录（Prompt Directory）**：存放提示词 Markdown 文件的本地文件夹，应用支持配置和监听该目录。
- **快捷粘贴悬浮窗（Prompt Picker / Floating Window）**：通过全局热键、命令行或外部消息呼出的无边框轻量级选择器浮层，用于快速过滤提示词并直接向呼出前所在的外部活动窗口发送文本。
- **Windows 消息激活（Windows Message Activation）**：通过 Windows 原生消息机制（`WM_COPYDATA`）由外部程序（如 AutoHotkey V2）向 KbcApp 传递控制指令以调度功能或切换窗口显隐。

## 用户故事

1. **跨应用即时唤出并选择粘贴**：作为开发者，在浏览器或聊天软件输入框中，我按下全局快捷键（或 AHK 发送消息），屏幕中央立即浮现轻量提示词选择器；我按方向键选中「详细解释」，按回车，悬浮窗立刻消失，几百字的 Prompt 瞬时粘贴进浏览器输入框中。
2. **打字即搜与无冲突移动**：作为开发者，悬浮窗弹出时光标已在输入框内，我输入 `fix` 即可精准过滤出「/fixp」提示词；在此过程中我无需使用鼠标或按下 Ctrl+F，随时敲击方向键即可上下选词，敲击回车即可提交。
3. **剪贴板不被污染**：作为开发者，我在编辑器中刚复制了一个变量名 `getUserToken`，然后唤出提示词选择器粘贴了一段提示词；粘贴完毕后我再次按下 `Ctrl+V`，剪贴板依然是我刚才复制的 `getUserToken`，原有数据没有被破坏。
4. **外部编辑器协作**：作为知识库管理者，我把提示词目录设置为自己的 Git/Obsidian 仓库目录；当我在外部 VS Code 中批量修改或新增 `.md` 文件后，KbcApp 管理页面与快捷悬浮窗自动识别最新内容。
5. **在主窗口中直观管理与编辑**：作为用户，我可以在主窗口 `/prompts` 页面浏览所有提示词卡片，修改触发词或标题，点击卡片直接用内嵌表单编辑正文，也可以点击“在文件管理器中定位”或“用默认编辑器打开”。
6. **开箱即用与预设引导**：初次打开该功能且目录为空时，软件自动生成常用的精品提示词示例（如详细解释、总结归纳、代码审查等），无需面对空空白白的手足无措。
7. **外部 AHK 联动与热字串**：作为 AHK 重度用户，我的 AHK 脚本可以读取该目录生成自身热字串，并在拦截到触发词时通过 `SendMessage` 调用 KbcApp 发送，或者呼出悬浮窗，体验浑然一体。

## 实现决定

### 1. 窗口架构与内存控制（遵循 ADR-0005）
- **单浮层多模式复用**：
  - 复用标签为 `"command-palette"` 的独立浮层窗口，不创建新的 Webview 实例；
  - 浮层内部根据调用指令切换模式：
    - `palette`：命令面板模式；
    - `prompt-picker`：快捷粘贴选择器模式；
  - 整体内存始终控制在 **40MB** 以下，无冗余进程。

### 2. 外部触发与通信协议（遵循 ADR-0006）
- **触发途径**：
  1. 系统全局热键（可配置，如 `Ctrl+Alt+P`）；
  2. 命令行调用：`kbcapp --route /prompts`（激活主窗口管理页）或 `kbcapp --picker prompts`（呼出悬浮窗）；
  3. Windows 消息：支持 AutoHotkey V2 等外部工具发送 `WM_COPYDATA` (0x004A)。
- **`WM_COPYDATA` 协议格式**：
  - 发送 JSON 字符串载荷：
    ```json
    { "action": "show_picker", "mode": "prompts" }
    ```
    或
    ```json
    { "action": "navigate", "route": "/prompts" }
    ```

### 3. 数据存储与文件规范
- **目录约定**：默认存储于 `%APPDATA%/KeyboardCommand/prompts/`，支持在设置中自定义任意本地文件夹。
- **文件格式**：
  ```markdown
  ---
  title: 详细解释
  command: eid
  ---

  请使用中文详细 有条理 逻辑推理清晰的解释/拆解...
  ```
- **文件名规则**：`[title].md`。编辑标题时自动重命名文件，非法字符（`\/:*?"<>|`）自动清洗为下划线。同名冲突时弹窗提示并阻止或由用户确认覆写。
- **容错解析**：
  - 无 FrontMatter 时：以文件名作为 `title`，全部内容作为 `content`；
  - FrontMatter 语法错误时：在卡片呈现警告标记，降级读取正文，确保不崩溃。

### 4. 粘贴与剪贴板控制
- **执行流程**：
  1. 记录当前前台窗口句柄（`GetForegroundWindow`）；
  2. 用户在悬浮窗确认选中提示词；
  3. 悬浮窗调用 `window.hide()`；
  4. 恢复先前记录的前台窗口焦点；
  5. 备份当前系统剪贴板内容；
  6. 将选中的提示词正文写入系统剪贴板；
  7. 模拟触发键盘 `Ctrl + V` 发送；
  8. 延迟 400ms 后，将备份的剪贴板内容还原写回系统剪贴板（设置中提供可关闭开关）。
