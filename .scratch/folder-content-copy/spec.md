# 文件夹浏览与文件上下文包复制规格

Type: spec
Label: ready-for-agent
Status: ready-for-agent

## 问题陈述

开发者需要频繁从本地项目中挑选相关文件，并将目录结构与源码一起提供给网页聊天式 AI 工具。手工查找、读取和复制多个文件费时，也容易遗漏路径信息。当前 playground 已实现目标页面的 UI 与交互原型，但使用模拟数据和浏览器状态，尚未接入真实文件系统、SQLite、文件历史、剪贴板和 Windows 应用能力。

## 解决方案

建立 Windows 桌面应用 `/folder-copy` 功能：沿用 playground 中已经设计并实现的页面 UI 与交互，将其接入 Tauri 2/Rust 能力，浏览并筛选本地目录，选择文件后生成文件上下文包并复制到系统剪贴板，同时保留可恢复的历史记录和可配置规则。

实现以 Rust 提供文件系统、搜索、SQLite、历史快照、剪贴板及桌面集成能力；React 页面按现有设计接入这些能力，不重新设计视觉和交互。项目当前没有根应用源码，因此需要按已决定的 Tauri 官方 React/TypeScript 脚手架初始化，并将 playground 页面迁入应用。

## 用户故事

1. 作为开发者，我想选择、输入或从最近使用列表中选择一个目录，以便快速浏览目标项目。
2. 作为开发者，我想看到真实目录树及文件/文件夹区分，以便了解项目结构。
3. 作为开发者，我想在目录子项很多时分批加载，以便浏览大目录时保持界面响应。
4. 作为开发者，我想按规则隐藏不可复制文件并标记忽略目录，以便目录树只呈现可用内容和明确的排除状态。
5. 作为开发者，我想按相对路径搜索文件或目录并定位到树节点，以便快速找到目标。
6. 作为开发者，我想用键盘浏览树、展开目录和切换文件选择，以便不依赖鼠标完成导航。
7. 作为开发者，我想递归选择目录并查看三态选择反馈，以便一次纳入多个可复制文件。
8. 作为开发者，我想查看已选文件及其大小并复制相对路径清单，以便管理和复用待复制内容。
9. 作为开发者，我想复制选中的文件上下文包并预览其 Markdown，以便将准确内容粘贴到其他工具。
10. 作为开发者，我想在树中右键单独复制一个可选文件，以便临时复制单个文件而不改变原选择。
11. 作为开发者，我想从搜索结果连续切换文件选择或定位目录，以便快速处理多个匹配项。
12. 作为开发者，我想查看、复制、重读或删除历史记录，以便复用旧快照或获取源文件的当前内容。
13. 作为开发者，我想重新打开目录时恢复最新历史记录中仍有效的文件选择，以便继续之前的工作。
14. 作为开发者，我想配置文件白名单、排除规则、忽略目录和大目录阈值，以便适配不同项目。
15. 作为开发者，我想在设置读写失败时看到错误并保留尚未保存的修改，以便安全重试或放弃。
16. 作为开发者，我想切换跟随系统、浅色和深色主题，以便按使用环境调整外观。
17. 作为开发者，我想从系统设置查看应用版本、更新状态、存储状态和快捷键，以便了解应用运行情况。
18. 作为自动化用户，我想通过 `kbcapp --route <功能路径>` 启动或切换到指定页面，以便从 AHK、PowerShell 或命令行调用应用。
19. 作为开发者，我想在重启应用后仍能从最近文件夹中选到之前浏览过的目录，以便不必重新输入路径。

## 实现决定

- 使用 Tauri 2、Rust、React、TypeScript、Vite 和 TanStack Router 客户端路由；不使用 SSR。bun 是唯一前端包管理器，Node.js 和 bun 沿用当前环境版本。Rust 稳定版精确固定并按需手动升级。
- 项目使用 Tauri 官方 React/TypeScript 脚手架。保留脚手架的开发和构建命令，不新增自动化测试框架、lint、格式化、类型检查、统一检查命令或提交钩子。
- `/folder-copy` 是默认页面和无参数启动页面。外部目标路径经过白名单校验；无效冷启动请求回退默认页并提示，无效运行中请求保留当前页面并提示。有效请求显示、恢复、聚焦窗口并导航。使用官方单实例插件转交后续启动参数；首版不注册 URI Scheme。
- playground 的页面布局、组件呈现、交互和反馈是 UI 实现基准。允许将现有 React 页面迁入应用并调整为真实数据源；不得借接入后端之机重新设计 UI。页面和后端以用户可见的命令/事件边界衔接。
- Rust 负责原生目录选择、目录扫描、fd 搜索调用、文件读取、文件上下文包生成、系统剪贴板、SQLite 配置、历史 sidecar 文件和系统集成。前端只保留页面状态、展示和交互编排；模拟数据不能作为正式运行数据源。
- 目录选择由系统对话框完成。树浏览遵循名称白名单、文件/文件夹排除规则和忽略目录配置。白名单支持扩展名和特殊文件名；默认排除锁文件、明显生成文件；敏感文本文件按普通白名单规则处理，不扫描内容中的密钥。排除规则大小写不敏感，`*` 通配；尾部 `/` 表示目录规则。忽略目录按目录名应用于根目录下任意层级，忽略和排除目录显示标记且不可展开。
- 单目录直接子项超过配置阈值时启用按需分页，默认阈值 50、每批 30 项。递归选择只纳入符合当前规则且未忽略的文件，目录以全选、部分选中、未选中三态呈现。
- 搜索使用用户自行安装的 `fd`，应用不打包 fd。搜索覆盖 fd 默认跳过的隐藏/忽略项，再执行应用规则筛选；按大小写不敏感的相对路径子串匹配，输入停止 500 毫秒后查询，最多显示 10 项并提示更多结果。fd 不可用时禁用输入并显示安装提示；部分遍历失败时保留已有结果并提示不完整。`Ctrl+F` 聚焦搜索，匹配文本高亮；搜索列表上下键移动高亮，Enter 对文件切换选择并保持列表打开，对目录只定位并展开。
- 文件树上下键只移动焦点；Space 和 Enter 对目录展开/关闭、对文件切换选择；右方向键展开目录或聚焦首个子项，左方向键折叠目录或聚焦父目录。忽略目录不可展开。保留 playground 设计的批量展开、全部折叠、全选和清空操作。
- 文件树仅在有效可选节点上显示右键菜单。可选文件节点提供“仅复制当前文件”和“在文件资源管理器中显示”；可选文件夹节点只提供“在文件资源管理器中显示”。文件复制生成单文件文件上下文包、写剪贴板并新增历史；文件管理器定位文件节点时打开并定位所在目录，定位文件夹节点时直接打开该文件夹。忽略或排除文件夹不显示菜单且无右键操作。以上操作不改变既有选择集合；菜单可通过点击外部、Esc 或滚动关闭。文件管理器启动失败时显示中文错误提示。
- 主复制按钮和 `Ctrl+Shift+C` 复制当前选择。读取任一文件失败时取消整次普通复制，保留剪贴板和选择并显示失败路径及可获得原因。剪贴板写入失败同样必须反馈，不能新增成功历史。
- 文件上下文包格式以 playground 现有生成器和 `design.md` 的正式描述为准：包含文件数、生成时间、来源根目录、文件清单及文件内容区块；区块使用相对路径标题、按文件类型标记的 Markdown 代码围栏和完整文件内容。此决定取代 issue 31 的逐文件绝对路径标题及其精确换行规范。新格式须由真实 Rust 生成并用于复制、预览和历史快照。
- 已选列表显示文件大小和总字节数；用户可移除单项、清空选择或复制相对路径清单。文件大小只用于界面统计，不作为额外注释写入文件上下文包。文件内容预览显示将要复制的 Markdown。不实现 Token 估算。
- 复制历史每次代表一个成功写入剪贴板的文件上下文包。历史记录包括创建时间、来源目录、文件数、文件列表和完整包快照；可按当前目录筛选或查看全部，按创建时间倒序显示；列表时间使用“刚刚”“N 分钟前”等相对格式，悬停可查看本地完整时间；显示每 30 秒刷新。全局最多 20 条，超限淘汰最早记录。
- 加载或切换文件夹后，复制历史面板强制只显示该文件夹的记录，即使用户此前手动切到“所有文件夹”；该补充口径见 [issue 33](issues/33-history-list-scope-and-order.md) 和 [issue 49](issues/49-recent-folder-list.md)。按目录筛选历史、最近文件夹去重和记录的来源目录匹配统一使用同一归一化路径比较（大小写不敏感、反斜杠转正斜杠、忽略尾部斜杠），显示与存储保留用户原始写法。
- 历史记录由配对 `.meta.json` 和 `.md` 文件保存；正文文件只包含文件上下文包。新增先写正文再发布元数据；删除先删除元数据；启动或维护时清理没有元数据的孤立正文。该决定遵循 ADR-0003；历史包正文和元数据不写入 SQLite。
- 历史快照的落盘目录、读写归属、原子写入、记录命名与读取失败语义见 [issue 48](issues/48-history-snapshot-storage.md)：与设置数据库同根的 `history\` 子目录、自定义 Rust 命令读写、单文件临时文件加原子重命名、`<毫秒时间戳>-<随机后缀>` 标识、启动只读元数据并在预览或复制快照时懒加载正文。复制成功但写盘失败时复制仍报成功并单独提示历史保存失败，该条不进入历史列表；目录整体不可读时历史按空处理且不阻塞文件夹加载。
- 加载目录时，以最新历史选择为参考，仅恢复仍存在且符合当前规则的文件；失效选择静默跳过。历史快照复制不重读文件、不刷新时间。历史“读取当前文件”忽略失败项；有成功文件时复制新包并替换该历史记录，全部失败时保留旧记录和剪贴板。遵循 ADR-0001。
- 设置弹窗从 SQLite 读取文件规则；无记录时呈现默认设置。白名单、排除规则、忽略目录和分页阈值在一个事务中保存。读取失败时禁用表单并允许重试/关闭；保存失败时回滚、保留草稿和页面状态，不关闭弹窗或重载目录。错误用中文摘要显示，可展开技术详情。成功保存后重载当前目录。
- 最近文件夹最多 10 条，写死不可配置，只保存路径字符串。每次成功加载文件夹（对话框选择、手动输入、下拉选择、外部激活走同一加载流程）写入或更新设置数据库中的单表记录，按最后使用时间倒序读取；加载失败不写入，从下拉选择死路径失败时提示中文错误并移除该条。首版不提供清空和单条删除入口。详见 [issue 49](issues/49-recent-folder-list.md)。
- 全局系统设置展示并控制主题模式（system/light/dark）；跟随系统模式实时响应操作系统明暗变化。SQLite 状态、存储路径/占用、应用版本与更新状态、全局快捷键展示应来自实际应用状态，不得使用固定演示值。系统启动、通知和自动更新开关仅在相应 Rust/系统能力成功接入后呈现为可操作功能。
- 保留 playground 的折叠式状态预设条，供开发和验收人员检查其定义的 13 种界面状态；预设数据只用于状态演示，不得伪造正式文件系统、数据库或历史结果。
- 当前代码库无应用源码或既有自动化测试可复用。规格验收以最高可用边界进行：页面通过真实 Tauri 命令完成完整用户流程；每张实现票据结束前，先使用 ego-browser 检视 playground 对应页面和交互并对照设计，再在已接入 Rust 的应用中手动验收该票据的端到端行为。此检查要求贯穿所有实现票据，不因票据只改 Rust 而省略。
- 领域实现优先复用成熟平台和 Tauri 官方能力；具体依赖选型和 API 用法在对应实现票据开始前按项目要求调研，不从零复制成熟基础设施。

## 测试决定

- 只验证用户可观察行为，不把内部函数调用顺序或具体模块结构作为验收条件。
- 每个端到端场景应覆盖真实 UI 与 Rust 命令边界，包括成功、失败和状态保留；每张实现票据完成前，先用 ego-browser 检查对应 playground 页面/交互与设计一致，再手动验证接入 Rust 后的流程。
- 不增加自动化测试框架或测试命令。该决定遵循 issue 30；目前代码库没有既有测试模块或可参考的同类测试。playground 的 StatePresetBar 提供需要手动检查的界面场景参考，不替代真实后端验收。

## 范围外

- 提示词列表、待办以及其他未来独立快捷功能。
- 重新设计 playground 已完成的页面视觉或交互。
- 打包发布、签名、更新服务端及发布通道的部署配置；实现前需具备相应发行环境。
- 自定义 URI Scheme 和通过浏览器链接唤起应用。
- 将文件上下文包正文或历史元数据迁入 SQLite。
- 最近文件夹的清空、单条删除等管理界面，以及历史快照存储目录的用户自定义。
- 将 fd、fzf、rg 或 Everything ES 打包为应用依赖；fd 由用户自行安装。
