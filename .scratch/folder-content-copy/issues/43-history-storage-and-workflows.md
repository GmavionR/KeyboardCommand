# 43：持久化并管理复制历史

**要构建：** 用户能查看和管理可恢复的复制历史；每次成功复制的快照在应用重启后仍可用。

**阻塞于：** [浏览真实目录并加载文件树](38-directory-tree-and-pagination.md)、[复制文件上下文包](42-copy-context-package.md)、[确定历史快照的落盘位置、读写归属与失败语义](48-history-snapshot-storage.md)

**状态：** resolved
**标签：** ready-for-agent

**设计来源：** playground 已随 issue 46 删除，历史面板与菜单改以 `docs/design/文件夹复制界面绘制说明.md` 为基准；持久化及恢复规则见 `.scratch/folder-content-copy/spec.md`、ADR-0001 和 ADR-0003。

- [x] 每条历史由 `.meta.json` 元数据和 `.md` 正文配对保存；正文仅为完整上下文包。新增先写正文再发布元数据，删除先移除元数据，并清理孤立正文。落盘位置 `%APPDATA%\com.keyboardcommand.app\history\`，实现见新增的 `src-tauri/src/history_store.rs`（`std::fs` + `.tmp` 再 rename 的原子写，不引入 `tauri-plugin-fs`，因此不需要新的 WebView 权限）。
- [x] 每次成功复制建立记录，保存创建时间、来源目录、文件数、文件列表和包快照；全局最多 20 条，按时间从新到旧显示，超限淘汰最早记录。元数据字段为 `id / createdAt(毫秒) / sourceFolder / fileCount / filePaths / bodyFileName`，正文只在查看快照或复制快照时懒读取。
- [x] 有当前目录时默认只显示该目录记录，可切换全部目录；没有当前目录时显示全部记录，并呈现设计规定的空状态。本轮修正：路径为空时原先恒显示空列表，现在「当前目录」按钮置灰、「全部」高亮。
- [x] 复制历史快照不重读源文件、不刷新创建时间；“读取当前文件”逐项重读，部分失败时复制成功文件并替换当前记录，全部失败时保留旧记录和剪贴板。替换走 `replace_history`：先写新记录一对，再删旧记录一对。
- [x] 删除历史后不可继续显示该记录；重新加载目录时仅恢复路径仍存在且符合当前规则的最新历史选择，失效项静默跳过。过滤由新增命令 `filter_selectable_paths` 完成，它复用上下文包的路径解析与规则判定，不另写一套规则。
- [x] 逐条完成前，先对照设计基准检视页面与交互，再在桌面应用中手动验收重启持久化、筛选、快照复制、重读成功/部分失败/全失败、删除和恢复选择。（原步骤要求先用 ego-browser 检视 playground；playground 已删除，按总规格决定改为以绘制说明文档为基准在运行中的应用内检视。）

## Comments

- 前端不再自己拼历史列表：`list_history` 是磁盘事实的投影，每次写入/替换/删除后重新读取，因此淘汰、替换和 20 条上限不可能与磁盘漂移；代价是每次复制多一次目录扫描（≤20 条，可接受）。
- `CopyHistoryItem` 与落盘元数据同形：删掉 `packageSnapshot` 和冗余的 `timestamp`，改为 `createdAt`(Unix 毫秒) + `bodyFileName`。正文不常驻内存，否则 20 条大包会把历史面板变成内存黑洞。
- 提示语义受“单条 toast”约束：复制成功但历史写盘失败时，只提示「复制成功，但该条历史未能保存」，不再叠加成功提示；该条不进入列表（与规格“写盘失败不回滚剪贴板、也不伪造记录”一致）。
- 自查发现并发误删风险：孤儿清理原本见到没有配对元数据的 `.md` 就删，而发布顺序正是“先正文后元数据”，同目录并发的 `list_history` 可能删掉正在写入的正文，留下读不出正文的记录。现在正文与 `.tmp` 一样只在修改时间超过 300 秒后才回收。
- 验收中发现 UI 缺陷：菜单原先 `absolute` 贴在卡片内，被历史列表的 `overflow-y-auto` 容器在顶边裁掉首行「读取当前文件」。改法和文件树右键菜单一致——`position: fixed` + 触发按钮视口坐标并夹在窗口内、上方放不下就向下展开，并自行接外点/Esc/滚动关闭。
- 状态预设「8. 无历史记录」在落盘后不能再清空真实历史：改为只影响显示的 `presetEmptyHistory` 开关，磁盘记录一条不动，提示文案明确“仅演示空状态，真实历史记录未被改动”。

## 验收记录

机器证据（直接读取 `%APPDATA%\com.keyboardcommand.app\history\`）：

- 用户验收跑完后目录内 3 条记录 = 3 对文件，`.tmp` 残留 0 个，删除过的记录没有留下孤儿正文。
- 元数据为 camelCase，字段齐全，`id` 形如 `1794390775239-4aa364`（毫秒 + 6 位十六进制），`createdAt` 与正文里的“生成时间”同源。
- 正文文件就是完整上下文包（`### 文件上下文包 (2 个文件)` 开头，含文件清单与 `#### [FILE: src/Demo.tsx]` 区块），没有额外包装。
- `cargo check` 与 `bun run build` 均无错误无告警。

用户桌面验收（夹具 `%TEMP%\kbc43-demo`）：重启后历史仍在、当前目录/全部筛选、复制已保存内容不重读不刷新时间、查看快照、重读成功/部分失败/全失败、删除此条历史、重新载入恢复仍有效的选择、状态预设「8. 无历史记录」只演示——均回复正常；菜单遮挡修复后复测正常。
