# 为超过可配置阈值的大目录设计分批加载交互

Type: prototype
Status: resolved

## 已确认前提

- 单个文件夹的直接子项超过 50 个时默认视为大目录；该阈值可以配置。
- 设置入口是统一的本功能设置弹窗；保存后重新加载当前文件夹。

## 问题

超过阈值后，首批显示多少子项、每次“加载更多”增加多少项？用什么状态提示让用户知道还有未加载内容？制作一个粗略目录树原型，用“子项很多但层级较浅”和“子项较少但层级很深”两组示例供用户评估。

## 原型

完整原型源文件保存在本地临时分支 `prototype/large-directory-loading`，提交 `55e80be`。该分支仅保存原型，主线保留验证后的决定。

## 答案

- 交互采用“树内追加”：已显示的子项保持原位，新批次追加在当前目录列表末尾。
- 列表末尾显示已显示数量、剩余数量和“加载更多”按钮；加载完成后更新计数并追加条目。
- 深层目录按当前文件夹的直接子项独立判断是否分批，不按整棵树的后代总数判断。
- 首批显示数量和每次点击追加数量已由 [issue 28](28-large-directory-batch-size.md) 确定为 30 项。
