# 确定历史快照的落盘位置、读写归属与失败语义

Type: grilling
Status: resolved

## 问题

[持久化并管理复制历史](43-history-storage-and-workflows.md) 要求复制历史跨重启可用，并已按 [ADR-0003](../../../docs/adr/0003-history-sidecar-files.md) 确定使用 `.meta.json` 与 `.md` 配对文件、不写入 SQLite。但仍未决定：文件落在哪个目录、由谁执行读写、单个文件如何原子写入、记录标识如何命名，以及读取失败时用户看到什么。

## 答案

- **落盘位置**：与设置数据库同根的 `<appDataDir()>\history\` 子目录，Windows 实测为 `%APPDATA%\com.keyboardcommand.app\history\`。Tauri 2 在 Windows 上 `appConfigDir()` 与 `appDataDir()` 解析为同一目录，因此历史与 `settings.db` 位于同一根下。目录不存在时由写入流程创建。**不提供用户自定义存储目录**，避免引入路径失效与迁移处理。
  - 取舍：历史正文是 20 条完整文件上下文包，体积由用户选择了哪些文件决定、不可控；放在 Roaming 下会随域账号登录同步。用户明确要求应用数据统一在一处、便于排查和备份，按简单化原则接受该代价。
- **读写归属**：自定义 Rust 命令 + `std::fs`，与现有 `load_directory_tree`、`load_directory_page`、`list_selectable_files` 同一路数。不引入 `tauri-plugin-fs`，不给 WebView 文件系统写权限。
- **单文件原子性**：每个文件先写同名 `.tmp`，再 `rename` 覆盖目标（同目录内为原子替换）。记录级顺序仍遵循 ADR-0003：先写正文、后写元数据，元数据是发布标记。
- **孤儿清理时机**：启动加载历史列表时扫描一次目录，删除没有配对元数据的 `.md`；按 [issue 15](15-history-eviction-policy.md) 淘汰超限时删除整个文件对。不设后台维护任务。
- **记录标识与命名**：`<Unix 毫秒时间戳>-<6 位随机十六进制>`，文件为 `<标识>.meta.json` 和 `<标识>.md`。现有 `hist-${Date.now()}` 在同一毫秒内会碰撞，弃用。
- **元数据字段**：`id`、`createdAt`（Unix 毫秒）、`sourceFolder`（绝对路径）、`filePaths`（相对 `sourceFolder` 的路径，与文件上下文包的相对路径口径一致）、`bodyFileName`。`bodyFileName` 虽可由 `id` 推导，仍按 ADR-0003 保留该字段，使日后更改命名规则时无需迁移已有元数据。UI 的时间和相对时间显示由 `createdAt` 派生，不另存格式化字符串。
- **加载时机**：启动只读元数据构建列表；`.md` 正文在用户预览或复制历史快照时才读。
- **复制成功但历史写盘失败**：复制仍报成功（正文已交付剪贴板，无法回滚），另给一条独立的中文「历史保存失败」提示，并且该条**不进入**历史列表——不允许出现重启后凭空消失的记录。
- **单条正文缺失或读取失败**：显示中文错误并附上缺失正文文件的完整路径，条目保留在列表中，由用户使用既有的删除按钮自行处理。不自动删除，避免一次瞬时读错误永久吃掉用户历史。
- **整个历史目录不可读**（目录被删、权限拒绝、所在盘断开）：历史列表按空处理并给一次性中文提示，**不阻塞**文件夹树加载、浏览与复制；下次复制仍会尝试创建目录并写入。
- 不实现 Token 估算，不改动 ADR-0003 的双文件布局本身。

## Comments

- 2026-11-11：与 [issue 20](20-history-file-layout.md)、[ADR-0003](../../../docs/adr/0003-history-sidecar-files.md) 一致。主流做法通常是「单文件临时文件 + 原子重命名」而非 sidecar 发布标记；本项目采用双文件是为了让 `.md` 正文保持可直接查看和复制，代价是必须有孤儿清理流程。已在 ADR-0003 补充这一偏差说明。
- 2026-11-11：落盘位置本可放 `appLocalDataDir()` 以避免大文件漫游同步，用户选择与设置同根的统一路径，本票按该决定记录。
