# 定义文件与文件夹名称排除规则的匹配和呈现方式

Type: grilling
Status: resolved

## 问题

用户已决定设置中提供全局可编辑的文件名/文件夹名排除规则，并在白名单之后应用。本票据确定规则语义、树中呈现、各流程的一致性及设置编辑方式。

## 答案

- 规则只匹配名称，不写路径；相对于当前选中的文件夹，在其任意层级匹配。
- ~~`*` 可匹配名称中的任意字符，但不跨目录；不支持 `?` 或反向规则。名称匹配不区分大小写。~~ 已被 [issue 51](51-substring-rule-matching.md) 取代：改为「名称包含规则文本即命中」，无通配符，名称匹配仍不区分大小写。
- 规则末尾带 `/` 表示只匹配文件夹；文件夹命中后，其全部后代一并排除。不带 `/` 表示只匹配文件。例如 `node_modules/` 匹配任意层级中名称含 `node_modules` 的文件夹，`.key` 匹配任意层级中名称含 `.key` 的文件。
- 被排除的文件在树中隐藏；被排除的文件夹作为“已排除”节点显示，不展开或遍历其后代。递归选择跳过排除项。
- 文件树、实时搜索、递归选择及历史选择恢复使用一致的排除规则。历史选择恢复时，当前被排除的文件静默跳过；历史记录与其快照不变。
- 设置弹窗以一行一条规则的列表编辑，支持新增、删除及恢复默认。默认规则允许编辑或删除。
- 默认文件排除项沿用 [issue 21](21-default-extension-list.md) 中决定的 `.DS_Store`、锁文件和明显生成文件规则；敏感文件仍可按普通白名单文件处理，用户可通过排除规则主动隐藏。
- 实时搜索把忽略目录以 `name/`、目录排除规则以 `*text*/` 传给 `fd --exclude` 剪枝；文件排除规则由应用对 `fd` 返回的文件结果应用。实测 fd 的 glob 尾斜杠只匹配目录路径，因此这两种写法都不会误伤同名文件（不带尾斜杠的 `*text*` 才会）。写法与实测依据见 [issue 52](52-fd-gitignore-and-dev-command.md)。[fd 官方文档](https://github.com/sharkdp/fd#excluding-specific-files-or-directories)
