# 确定设置数据库读写失败时的反馈

Type: grilling
Status: resolved

## 问题

设置弹窗打开时需要从 SQLite 查询配置，保存时写入 SQLite 并重新加载当前文件夹。本票据确定读取无记录、读写失败及重试时的反馈和页面状态。

## 答案

- 查询成功但数据库中尚无设置记录时，显示默认设置并允许编辑。
- 查询失败时不得将错误伪装成“没有设置记录”，也不显示可编辑的设置表单或允许保存。弹窗显示读取失败提示和“重试”操作，允许关闭弹窗；重试成功后载入配置并启用编辑，重试失败则继续显示错误状态。主页面保持不变。
- 保存全部设置使用同一数据库事务；任一项写入失败时回滚，不留下部分更新。
- 保存失败时保留弹窗及所有未保存修改，不重新加载文件夹，也不改变当前已生效配置。用户可以重试；选择取消则关闭弹窗并放弃未保存修改。
- 面向用户的提示使用中文，说明失败的操作和下一步，例如“设置未保存，你的修改仍保留，请重试”。原始技术原因可通过“查看详情”展开；主提示不展示堆栈或原始数据库错误。
- 保存成功时沿用 [issue 24](24-database-workflow-responsibility.md) 的决定：关闭弹窗并重新加载当前文件夹。

## Comments

- 用户确认查询成功但无记录时使用默认设置；实际查询失败时禁用编辑、提供重试并允许关闭。
- 用户确认保存事务失败时回滚，保留草稿、当前配置和页面状态；用户可重试或取消。
- 用户确认错误提示采用中文摘要，技术原因可展开查看。
