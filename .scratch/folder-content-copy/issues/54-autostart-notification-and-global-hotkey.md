# 54：接入开机自启、桌面通知与系统级全局快捷键

Type: task
Status: open
Label: ready-for-agent

## 要构建

系统设置里出现真正生效的开机自启开关、桌面通知开关，以及能在应用失焦时触发的系统级全局快捷键；操作失败时给出中文反馈。

## 为什么单独成票

[issue 44](44-system-settings-and-desktop-integrations.md) 原来的第三项要求「按设计接入系统启动和桌面通知控制」。核查后发现，这三项此前在界面上都是**假控制**：

- 「Windows 开机时在后台托盘自启动」和「复制成功或失败时显示 Windows 原生桌面系统通知」两个复选框只写 React `useState`，不落任何存储、不调任何原生能力，勾选后重启即复位，勾了也不生效。
- 「复制上下文包全局快捷键 Ctrl + Shift + C」被标为系统级，实际是 `window` 上的 `keydown` 监听（`src/FolderCopyApp.tsx:476`），应用失焦时不生效。

用户在 issue 44 选定范围「只做诚实化，零新依赖」，因此这三项在 44 里被删除或改名，不在 44 里引入新插件。本票据承接真正的能力接入。

外部演示项目 design.md 第 4.1 节定义的全局系统设置只有四组（外观主题、应用更新、存储核心、快捷键清单），本来就不含自启与通知开关；这两个开关是 mock 实现自行加的。接入时应先确认是否仍要放进系统设置，以及放在哪一组。

## 待明确

- 三项能力各自的官方插件选型与权限范围（自启、通知、全局快捷键），按项目要求先调研成熟做法再动手，不从零手搓注册表或 Win32 调用。
- 自启是「开机后驻留托盘」还是「开机后打开主窗口」——当前应用没有托盘实现，选前者要先补托盘。
- 全局快捷键与 `Ctrl + Shift + C` 现有的应用内监听如何共存，注册冲突（被其他应用占用）时如何反馈。
- 通知在复制成功/失败时的触发点，与现有 Toast 的关系（是否两者都出）。
