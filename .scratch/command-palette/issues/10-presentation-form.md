# 10：命令面板的呈现形态——一套独立窗口还是两套形态

Type: grilling
Status: resolved
Label: ready-for-agent

## 决议

**统一为单套常驻后台的独立浮层窗口**（Spotlight / Raycast 风格），放弃「托盘时独立窗口、主窗口显示时页内遮罩」的两套形态方案。

### 核心规则

1. **唯一形态**：无论主窗口在托盘、最小化、被遮挡还是在当前屏幕，按下唤起热键（默认 `Ctrl+Shift+K`）一律呼出屏幕居中偏上的独立轻量无边框 Webview 窗口。
2. **预创建隐藏复用**：应用启动时预先创建该面板窗口，初始状态为隐藏（`visible: false`）。热键触发时直接调用 `show()` 与 `set_focus()`，实现 0 毫秒级即时呼出，避免动态创建的白屏与加载延迟。
3. **失焦与取消**：按 Escape 键或鼠标点击面板外部区域（失去焦点 `blur`）时，面板窗口自动 `hide()` 隐藏。
4. **跳转与执行**：
   - 执行跳转命令（如打开某一功能页面）时，面板隐藏，主窗口调用 `show()`、`unminimize()`、`set_focus()` 激活到当前屏幕前台，并切换到目标功能路径。
   - 执行动作命令（如切换深色/浅色外观）时，面板直接触发对应动作并隐藏。

### 决策理由与事实依据

1. **符合业界主流**：[issue 09](09-tauri-tray-hotkey-window-research.md) 调研核实，Raycast、uTools、PowerToys Run 等全局桌面效率标杆工具，无论主程序是否处于打开或前台状态，按热键均弹出同一个独立的居中搜索窗口。业界不存在维护两套完全不同外壳的先例。
2. **消除伪状态判定**：Win32 API 没有可靠高层接口判定窗口是否被遮挡或跨虚拟桌面。统一为独立窗口后，根本不需要计算主窗口的遮挡状态（自然消除了 [issue 11](11-window-visible-definition.md) 的复杂性）。
3. **降低工程维护成本**：只需维护一套基于 `cmdk` 的独立面板 Webview，不需要分别维护两套挂载外壳、两套焦点捕获与两套事件通信机制。
