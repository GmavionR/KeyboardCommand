# 10：命令面板的呈现形态——一套独立窗口还是两套形态

Type: grilling
Status: open
Label: needs-triage
Blocked by: 09

## 问题

**这是当前最核心的未决问题，也是用户明确表示自己不确定的一点。**

[issue 02](02-system-hotkey-and-invocation.md) 中用户描述的规则是：

- 场景 1：应用没有窗口正在显示（仅托盘）→ 按热键显示一个搜索弹窗，「看起来却是一个 window 窗口」。
- 场景 2：应用有窗口正在显示（可能在别的虚拟桌面或被遮挡）→ 激活到前台，「在页面内显示一个弹窗遮罩，类似于 vscode 的命令面板」。

用户原话结尾：「我不确定是不是这样。」

需要决定的是：**这真的是两套呈现形态吗？** 三条路：

- **(a) 两套形态**：托盘态用独立无边框窗口，窗口态用页内遮罩。贴合用户描述，但要维护两套外壳、两套关闭/焦点语义（issue 06 与 issue 15），且同一个面板组件要能在两个 webview 入口里挂载。
- **(b) 统一为独立窗口**：无论主窗口是否显示，热键都唤起同一个独立无边框面板窗口。只有一套实现、一套焦点语义，形态与 Raycast / uTools / PowerToys Run 一致。代价是「有主窗口时」不再是页内遮罩，与用户描述的场景 2 不同；执行跳转命令时需要额外把主窗口激活到前台。
- **(c) 统一为页内遮罩**：托盘态先把主窗口显示出来再开遮罩。实现最省，但托盘态会连带弹出一个完整主窗口，与「只想要一个快速搜索框」的意图相悖。

## 决策需要的输入

- [issue 09](09-tauri-tray-hotkey-window-research.md) 的平台能力事实与参考产品形态。
- 本票的结论会决定 [issue 15](15-standalone-window-close-behavior.md)、[issue 16](16-panel-position-and-monitors.md)、[issue 19](19-theme-scope-and-sync.md)、[issue 21](21-panel-visual-details.md) 是否成立以及怎么问。

## 提问时的倾向

倾向 **(b) 统一为独立窗口**：一套实现、一套语义，且是这类工具的主流形态；用户描述的「两种看起来不一样」很可能只是对现象的猜测，而不是需求。但**必须先拿 issue 09 的事实核对**，尤其要确认独立窗口在执行跳转命令后能否可靠地把主窗口带到前台（含跨虚拟桌面）。若该能力不可靠，(b) 的优势会被削弱。

**此倾向未与用户确认，不构成决议。**
