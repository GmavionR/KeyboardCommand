# 03：命令分类只做分组标题，列表单层

Type: grilling
Status: resolved
Label: ready-for-agent

## 问题

用户要求命令面板里「有分类」。参考截图中其实存在两种不同的分类语义：

- 上半部分带 `→` 的条目（Blocks / Charts / Directory / Typeset / Create）看起来是**可下钻入口**：选中后进入下一层列表。
- 下半部分 `Styles` 是**分组标题**：组内直接列出条目。

两者交互模型完全不同。分组标题是一个扁平列表按分类分段，一次输入跨所有分类匹配；可下钻则是先选分类再在分类内搜索，输入只在当前层生效，还需要返回上层的面包屑。

## 答案

**只做分组标题，分类本身没有交互。** 用户原话：

> 分类是分组标题，只做分组，没有交互。`→` 这个符号只是表示当前是 url 页面跳转连接，并不表示下钻。而且列表是单层的，没见到过 enter 进入下一层列表的。

因此：

- 命令列表**永远是单层**，不存在进入下一层列表的操作。
- 分类只影响**分段展示与排列顺序**，不可选中、不可展开、不可执行。
- 一次输入**跨所有分类**匹配。
- `→` 符号是**跳转命令的类型标记**，与分类无关，不表示下钻。动作命令不带这个符号。

## Comments

- 2026-11-13：grilling 第一轮 Q3，用户否决了「下钻」的可能性并澄清了 `→` 的含义。
- 调研（见 [issue 08](08-prior-art-research.md)）显示下钻页栈确实是 cmdk / kbar / Raycast 的官方配方，VS Code 则用前缀符号（`>` / `@` / `#`）在同一个输入框里切换模式。本项目明确不采用这两种，保持单层。
- 分类的**具体名称与排列顺序**尚未确定，随命令清单一起定，见 [issue 20](20-command-inventory-and-availability.md)。
