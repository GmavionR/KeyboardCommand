# 11：「有窗口正在显示」的判定口径

Type: grilling
Status: open
Label: needs-triage
Blocked by: 09

## 问题

[issue 02](02-system-hotkey-and-invocation.md) 的两条规则以「当前应用有没有窗口正在显示」分流，但这个状态在 Windows 上不是布尔值。需要逐个定口径：

- **主窗口最小化**算「有窗口显示」还是「没有」？用户只举了「隐藏在系统托盘」作为「没有」的例子，最小化未提。
- **主窗口被其他应用完全遮挡**：用户明确说算「有窗口」，走激活到前台。但 Windows 上能否可靠检测「被遮挡」？若检测不到，是否退化为「只要窗口没被隐藏/最小化就算有」？
- **主窗口位于另一个虚拟桌面**：用户明确说算「有窗口」。跨虚拟桌面激活到前台在 Windows 上有已知限制，若激活失败怎么办——留在当前桌面开独立面板，还是强行切桌面？
- **主窗口可见但失焦**：显然算「有窗口」，但是否需要区分「失焦」和「被遮挡」？
- 判定发生在 **Rust 侧还是前端**？前端在窗口隐藏时是否还在运行、能否及时响应？

## 为什么单独成票

判定口径直接决定用户按一次热键后看到什么。口径模糊会导致「有时弹出小窗、有时弹出整个主窗口」的不一致体验，而这种不一致很难在事后调试。

若 [issue 10](10-presentation-form.md) 最终选择「统一为独立窗口」，本票的大部分内容会简化甚至消失——但**最小化与跨虚拟桌面的激活行为仍然要定**，因为跳转命令执行后总要把主窗口带到前台。
